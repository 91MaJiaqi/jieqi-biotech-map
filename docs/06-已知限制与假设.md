## 2. 已知限制

1. **未执行 `docker-compose up` 实测**：本次构建环境无 Docker/docker-compose，因此改用
   uvicorn + vite 真实运行并验证了全部接口与页面（后端 pytest 23 项、前端 Playwright 10 项全部通过）。
   Docker 相关文件已编写但未在容器中跑通，**属于未实测项**。
2. **Playwright 自带 Chromium 未下载成功**：本机访问 `cdn.playwright.dev` 下载 197.5 MiB 的
   `chrome-win64.zip` 时长时间停滞在约 10%，因此改用系统已安装的 **Microsoft Edge**
   （配置为默认通道 `channel: 'msedge'`）完成全部 10 项浏览器测试并通过。
   测试代码本身与浏览器通道无关；在可正常下载的环境执行 `npx playwright install chromium`
   后设置 `PLAYWRIGHT_BROWSER=chromium` 即可切回自带 Chromium。
3. **PostgreSQL / Neo4j 未实测**：仅为预留配置与适配层设计，未实际切换验证。
4. **科普链接可达性未做在线校验**：程序只校验域名白名单，不发起网络请求验证 HTTP 200。
   机构改版可能导致个别链接失效（见 04 文档的维护建议）。
5. **关系数据规模有限**：26 条关系，覆盖 24 节气中的 10 个。未写入的节气并非空缺，而是未找到可核验来源，
   遵循「不编造」约束。
6. **气候模拟为示意模型**：不是气候模式输出，不能用于生产或科研；数值仅供交互演示。
7. **农谚证据强度天然偏低**：平台按「弱」处理，不应作为生产决策依据。
8. **地图底图依赖外部瓦片服务**（OpenStreetMap）：离线环境下底图不显示，但标记点与交互仍可用。
9. **前端首屏包较大**：ECharts + Leaflet + D3 合计使产物约 1.4 MB（gzip ≈ 465 KB），
   构建时有 chunk 体积提示。未做代码分割（MVP 取舍），后续可用 `manualChunks` 优化。
10. **无用户体系与权限**：平台为只读知识库，不涉及登录、写操作与审核流。
11. **D3.js 使用有限**：需求列举 D3.js，本项目在圆盘布局与坐标换算上使用 D3 生态的数学思路与
    ECharts/Leaflet 配合；未大量使用 D3 的 DOM 绑定能力（可扩展点）。

## 3. 下一步建议

1. 在具备 Docker 的环境执行 `docker compose up --build` 并补充容器化测试结论。
2. 增加链接健康检查脚本（定时 HEAD 请求），把失效链接写入维护清单。
3. 引入人工审核工作流：新增关系必须先给出可核验来源并通过审阅，再进入 `seed.json`。
4. 关系数据扩展到全部 24 节气与 12 项技术；对每条关系补充「适用条件/边界」字段。
5. 前端按路由做 `React.lazy` 代码分割，降低首屏体积。
6. 若关系规模超过数千条，切换到 Neo4j 并把 `build_graph()` 替换为 Cypher 查询。
